# ident

Identifiers for nodes, people and endpoints, the public-key type they are
derived from, and their text form. Read [../README.md](../README.md) first for
the conventions every contract package follows, and
[../../docs/references/identity/README.md](../../docs/references/identity/README.md)
for the reasoning.

## Entry points

| Type         | Size     | Meaning                                                                  |
| ------------ | -------- | ------------------------------------------------------------------------ |
| `NodeID`     | 32 bytes | A node. A digest of the node's long-term identity public key.            |
| `PersonID`   | 32 bytes | A person. A digest of the person's root public key.                      |
| `EndpointID` | 16 bytes | An endpoint on a node. Random, generated by that node.                   |
| `Address`    | -        | `{Node, Endpoint}`: one endpoint on one node.                            |
| `PublicKey`  | -        | A validated public key with its `Algorithm` tag (Ed25519 only for now).  |

- `NewPublicKey(alg, bytes)` accepts only `AlgorithmEd25519`, a canonical point
  encoding on the curve, and not a small-order point. `AlgorithmP256` is
  reserved and refused. `PublicKey.Verify(msg, sig)` is the one place a
  signature is checked.
- `NodeIDFromKey(k)` and `PersonIDFromKey(k)` derive an identifier: SHA-256 of
  `frame.Frame(domain, algorithm tag as one byte, canonical key bytes)`. The
  node and person domains differ, so one key yields unrelated identifiers in
  the two roles.

For each of the three identifier types `T`:

- `TFromBytes([]byte) (T, error)` rejects input of the wrong length and the
  all-zero value.
- `String()` writes bech32m text; `ParseT(string) (T, error)` reads it. The
  human-readable prefix names the kind: `node`, `person`, `ep`.
- `Bytes()` returns a copy; `IsZero()` reports the unset value.

`NewEndpointID(io.Reader)` reads a new `EndpointID` from the supplied
randomness source (callers pass `crypto/rand.Reader`) and rejects an all-zero
result. `ParseAddress` and `Address.String` use the form `<node>/<endpoint>`.

Errors wrap `ErrLength`, `ErrZero`, `ErrText`, `ErrPrefix` or `ErrChecksum` for
identifiers and `ErrAlgorithm`, `ErrKeyLength`, `ErrKeyNotCanonical` or
`ErrKeySmallOrder` for keys; match them with `errors.Is`.

## Invariants

- Lengths are fixed. The identifier types are structs with an unexported array,
  so a value cannot be built from a wrong-length slice, and they stay
  comparable and usable as map keys.
- The zero value means "unset" and is never a valid identifier or key:
  constructors and parsers refuse it, so a non-zero value obtained from this
  package is valid. An `Address` is zero if either part is.
- An `EndpointID` never changes once its node has issued it.
- Every identifier has exactly one text. The parser accepts only lowercase
  bech32m with the expected prefix and data length, zero padding bits and the
  bech32m checksum constant (not the older bech32 one), and re-encodes the
  result to compare. A string of another kind, such as a person text where a
  node is expected, fails with `ErrPrefix`.
- Every key has exactly one accepted encoding, so one key has one identifier.
  A non-canonical encoding, a point not on the curve and a small-order point are
  refused when the key is built; the signature check additionally refuses a
  non-canonical signature scalar.
- `ident` imports no contract package except the dependency-free
  [`frame`](../frame/README.md), whose one framing rule builds the derivation
  input and which declares the derivation domains. The key type lives
  here, and not next to the record format, because derivation takes a key and a
  derivation that depended on the record package would invert the dependency
  direction.
